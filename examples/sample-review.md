## AI Code Review: ⛔ Changes requested

This PR adds an average_age helper, a user search, pagination, and avatar loading. It has serious security problems. The search query is built by string concatenation, which allows SQL injection. load_avatar can read any file on the server (path traversal). An API key is hardcoded in the source. There are also bugs: an off-by-one in pagination, division by zero on an empty list, and leaked database connections and file handles.

**7 finding(s)** across 2 file(s): 🔴 2 critical · 🟠 2 high · 🟡 2 medium · 🔵 1 low

### Findings

**1. 🔴 SQL injection in search_users via string concatenation.**  
`app/users.py:19` · critical · security

User-controlled `name` is put straight into the SQL string. Input like `' OR 1=1 --` or a UNION payload can dump or change any table.

> **Suggestion:** Use a parameterized query: `db.execute("SELECT id, name, email FROM users WHERE name LIKE ?", (f"%{name}%",))`.

**2. 🔴 Path traversal in load_avatar.**  
`app/users.py:30` · critical · security

A `filename` like `../../etc/passwd` or an absolute path lets a caller read any file the process can access.

> **Suggestion:** Resolve the path and check that it stays inside the avatars directory: `base = Path('avatars').resolve(); p = (base / filename).resolve(); if not p.is_relative_to(base): raise ValueError`. Better still, allow only safe basenames.

**3. 🟠 API key hardcoded in source.**  
`app/users.py:3` · high · security

Secrets committed to the repo end up in version history and are visible to anyone with access to the code.

> **Suggestion:** Load the key from an environment variable or a secrets manager (`os.environ["API_KEY"]`) and rotate the exposed key.

**4. 🟠 Off-by-one in get_page: page 1 skips the first page.**  
`app/users.py:25` · high · bug

The docstring says pages start at 1, but `start = page * per_page` makes page 1 return items 10-19, so the first page can never be returned.

> **Suggestion:** Use `start = (page - 1) * per_page` and reject `page < 1`.

**5. 🟡 ZeroDivisionError when users is empty.**  
`app/stats.py:5` · medium · bug

`len(users)` is 0 for an empty list, so the function raises an unhandled exception.

> **Suggestion:** Return None or 0 for an empty list, or raise a clear ValueError: `if not users: return None`.

**6. 🟡 Database connection never closed in search_users.**  
`app/users.py:20` · medium · bug

Each call opens a sqlite connection and never closes it, so connections and file handles leak under load.

> **Suggestion:** Use `with closing(get_db()) as db:` or call db.close() in a try/finally block, as get_user does.

**7. 🔵 File handle leaked in load_avatar.**  
`app/users.py:30` · low · bug

The file is opened without being closed, so the handle stays open until garbage collection.

> **Suggestion:** `with open(path, 'rb') as f: return f.read()`.
